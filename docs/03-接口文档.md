# 03 · 接口文档

> 项目：**lab_reserve · 实验室预约管理系统**
> 版本：v1.0 ｜ 最后更新：2026-10-24
> 在线文档（可直接调试）：后端启动后访问 **http://localhost:8080/doc.html**（Knife4j）。
> 本文是接口清单与约定说明；字段级细节以 Knife4j 的 OpenAPI 为准（二者同源，不会打架）。

---

## 1. 通用约定

| 项 | 约定 |
|---|---|
| 风格 | 一律 `POST` + JSON body；**唯一例外** `POST /api/file/upload`（multipart 上传图片） |
| 鉴权 | 请求头 `Authorization: Bearer <accessToken>`；登录/健康检查免鉴权 |
| 响应 | 统一 `Result<T>`：`{ code, message, data, timestamp }` |
| 状态码 | **HTTP 状态码 == 响应体 `code`**；业务冲突统一 409 |
| 分页 | 请求体继承 `PageQuery`（`pageNum` / `pageSize`，`pageSize ≤ 100`）；响应 `PageResult<T>`（`records / total / pageNum / pageSize`） |
| 时间格式 | `yyyy-MM-dd HH:mm:ss`（日期 `yyyy-MM-dd`，时间 `HH:mm`） |
| 导出 | 返回 `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`，中文文件名 URL 编码 |

### 1.1 错误码

| code | 含义 | 典型场景 |
|---|---|---|
| 400 | 参数错误 | 校验失败、文件类型非法、缺更新原因 |
| 401 | 未登录 / token 失效 | 未带 token、黑名单、过期 |
| 403 | 无权限 | 角色缺少权限码、操作他人数据 |
| 404 | 不存在 | 资源 / 预约 / 工单 ID 不存在 |
| 409 | 业务冲突 | 编号重复、时段被占、库存不足、状态不允许、处于禁入期 |
| 500 | 服务异常 | OSS / SMTP 等外部依赖失败（业务数据不受影响时会明确提示） |

### 1.2 冲突码（`data.conflictCode`）

`check` / `create` / `queue/create` 冲突时返回 409，`data` 里带冲突码，前端据此提示：

| 冲突码 | 含义 |
|---|---|
| `SLOT_OCCUPIED` | 实验室时段已被占用（可排队） |
| `STOCK_NOT_ENOUGH` | 设备库存不足（可排队） |
| `EQUIPMENT_UNAVAILABLE` | 设备状态非正常（维修中/报废/停用） |
| `LAB_DISABLED` | 实验室已停用 |
| `CAPACITY_EXCEEDED` | 使用人数超过容纳人数 |
| `NOT_IN_OPEN_TIME` | 不在开放时间 / 非开放日 / 日期已过 |
| `ALREADY_RESERVED` | 本人该时段已有预约 |
| `LAB_RESERVE_TEACHER_ONLY` | 学生尝试预约实验室 |
| `CLASS_REQUIRED` | 教师预约实验室未选上课班级 |
| `EXPERIMENT_TYPE_NOT_SUPPORTED` | 实验类型与实验室不匹配 |
| `QUEUE_BANNED` | 处于 7 天排队禁入期（`data.banEndTime` 给解除时间） |
| `SLOT_AVAILABLE` | 时段还空着，应直接预约而不是排队 |
| `ALREADY_QUEUED` | 已在队列中（`data.position` 给当前顺位） |

## 2. 接口清单

> 权限列写的是 `@RequirePerm` 的权限码；「登录即可」表示只校验登录态。

### 2.1 认证 `/api/auth`

| 接口 | 权限 | 说明 |
|---|---|---|
| `login` / `refresh` / `logout` | 公开 / 公开 / 登录 | 登录（返回 Access + Refresh + 用户信息）、刷新、登出 |
| `get_info` | 登录 | 当前用户信息 + 权限码 + **菜单**（前端侧边栏来源） |
| `update_password` | 登录 | 改密后当前 Access 立即失效 |

### 2.2 系统 `/api/system`

| 接口 | 权限 | 说明 |
|---|---|---|
| `health` | 公开 | 只返回 `status`（docker 健康检查用） |
| `monitor` | `system:monitor:view` | MySQL / Redis 状态、运行时长、激活配置（仅 SYS_ADMIN） |

### 2.3 用户 `/api/user`

| 接口 | 权限 | 说明 |
|---|---|---|
| `get_page` / `get_info` / `create` / `update` / `update_status` | `user:list` / `user:view` / `user:create` / `user:update` / `user:disable` | 用户管理 |
| `get_self_profile` / `update_self` | 登录 | 个人中心（本人手机号明文） |
| `list_maintainer` | `user:list` 或 `repair:list` | 维修人员下拉（派单用） |
| `list_option` | 登录 | 用户下拉 |

> 手机号默认脱敏；`get_page`/`get_info` 传 `revealPhone=true` 且具备 `user:view-phone` 才返回明文，并写 `QUERY_PHONE` 日志。

### 2.4 班级 `/api/class`

`get_list`（登录即可，教师排课选班级）、`get_page` / `create` / `update`（`class:manage`）。

### 2.5 角色与权限 `/api/role`、`/api/permission`

`role/get_list`、`role/get_permission_list`（`system:role:list`）、`role/update_permission`（`system:role:update`，改完清缓存）、
`permission/get_list`（`system:permission:list`）。

### 2.6 资源 `/api/experiment_type`、`/api/time_slot`、`/api/laboratory`、`/api/equipment`、`/api/resource_log`

| 分组 | 接口 | 权限 |
|---|---|---|
| 实验类型 / 时段 | 各 4 个：`get_list` / `create` / `update` / `delete` | `dict:list` / `dict:manage` |
| 实验室 | `get_page` `get_info` `create` `update` `update_status` `list_option` `get_availability` | `resource:lab:list/create/update/disable`；下拉与可用性登录即可 |
| 设备 | 同名 7 个 | `resource:equip:*` |
| 资源更新日志 | `get_page` | `resource:log:list` |

> 资源写操作强制 `updateReason`；字典被引用时删除返回 409；`get_availability` 同时返回排队人数与我的顺位。

### 2.7 预约 `/api/reservation`（10）

| 接口 | 权限 | 说明 |
|---|---|---|
| `check` | 登录 | 预检（不落库），返回可约 / 冲突码 / 排队人数 / 禁入信息 |
| `create` | 登录 | 提交预约（锁内判冲 + 唯一索引兜底；冲突 409） |
| `get_page` | `reservation:list-all` | 管理端分页（状态/资源/日期/申请人/学院筛选） |
| `get_my_page` | 登录 | 我的预约 |
| `get_pending_page` | `reservation:audit` | 待审核列表 |
| `get_info` | 本人或 `reservation:view` | 详情（含附带设备、审核信息、调整待办） |
| `audit` | `reservation:audit` | 通过 / 驳回（驳回必填原因；通过时锁内二次判冲；都发站内信） |
| `cancel` | 登录 | 撤销（仅本人 + 仅 PENDING） |
| `release` | `reservation:release` | 管理员释放时段（置 CANCELED + 通知 + 触发候补顺延） |
| `get_my_timetable` | `reservation:timetable` | 我的实验课表（学生按班级反查） |

### 2.8 调整申请 `/api/reservation_change`（5）

`create`（`change:create`，24h 窗口 + 双快照，只改 status）、`get_list_by_reservation`（本人或管理员）、
`get_page`（`change:list`）、`audit`（`change:audit`，通过时锁内校验新时段 → 回写 → 释放旧时段）、`cancel`（`change:create`）。

### 2.9 排队与候补 `/api/queue`（9）、`/api/queue_ban`（1）

| 接口 | 权限 | 说明 |
|---|---|---|
| `queue/create` | `queue:create` | 加入排队（`ZADD NX` 幂等 + 排队号） |
| `queue/get_my_page` / `get_info` / `get_my_position` / `get_notice_list` | `queue:create` | 我的排队 / 详情 / 实时顺位 / 候补通知历史 |
| `queue/get_page` | `queue:list-all` | 某资源的完整队列（管理员） |
| `queue/cancel` | `queue:cancel` | 取消排队（不写禁入） |
| `queue/confirm` | `queue:confirm` | 候补确认 → **直接生成 APPROVED 预约单** |
| `queue/abandon` | `queue:confirm` | 放弃候补 → 7 天禁入 + 顺延 |
| `queue_ban/get_my_list` | 登录 | 我的禁入记录 |

### 2.10 设备运维 `/api/file`（1）、`/api/repair_order`（10）、`/api/repair_record`（1）

| 接口 | 权限 | 说明 |
|---|---|---|
| `file/upload` | 登录 | multipart 上传图片（≤5MB，jpg/png/webp，校验文件头魔数），返回 OSS URL |
| `repair_order/create` | `repair:create` | 提交报修（通知所有 LAB_ADMIN） |
| `repair_order/get_page` | `repair:list` | 工单分页（管理员） |
| `repair_order/get_my_submitted_page` | 登录 | 我的报修 |
| `repair_order/get_my_assigned_page` | `repair:list-assigned` | 我的维修任务 |
| `repair_order/get_info` | 本人/维修人/管理员 | 详情（含故障图片与维修时间线） |
| `repair_order/review` | `repair:review` | 复核（确认故障可改优先级/设备状态；驳回必填原因） |
| `repair_order/assign` | `repair:assign` | 派单（只能派 `MAINTAINER` 且账号正常） |
| `repair_order/update_progress` / `complete` | `repair:progress` | 维修人更新进度 / 完成维修（只能操作自己的工单） |
| `repair_order/accept` | `repair:accept` | 验收（PASS → 归档 + 设备恢复；FAIL → REOPENED） |
| `repair_record/get_list` | 登录 | 某工单的维修记录 |

### 2.11 消息 `/api/message`（10）

`get_page` / `get_info`（自动已读）/ `get_unread_count` / `read` / `read_all` / `delete` / `clear`（`message:list`）；
`get_delivery_log_page` / `send_test_email`（`message:delivery-log`，仅 SYS_ADMIN）；
`send`（`message:send`，SYS_ADMIN 发系统通知）。

### 2.12 统计 `/api/statistics`（7）

`get_overview` / `get_occupancy` / `get_experiment_type_ratio` / `get_success_rate` / `get_resource_ratio` /
`get_reservation_trend`（`stat:view`）；`export`（`stat:export`）。
公共入参：`beginDate` / `endDate` / `college` / `experimentTypeId` / `labId`；趋势额外 `groupBy=day|week|month`；
导出额外 `type=reservation|occupancy|experiment-type|success-rate|resource-ratio`。

### 2.13 操作日志 `/api/operation_log`（3）

`get_page` / `get_info`（`system:log:list`）、`export`（`system:log:export`）。日志由 `@OpLog` 切面自动写入，接口只读。

## 4. 调试与联调建议

1. 启动后打开 http://localhost:8080/doc.html ，先在「认证 → login」拿 token，
   点右上角「Authorize」填入 `Bearer <token>`，后续接口自动带鉴权；
2. 冲突类接口建议先用 `check` / `get_availability` 看当前占用，再调用写接口；
3. 导出类接口在 Knife4j 里可能无法直接下载文件，用 curl 或前端页面更直观：
   ```bash
   curl -X POST http://localhost:8080/api/statistics/export \
     -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
     -d '{"beginDate":"2026-10-01","endDate":"2026-10-31","type":"reservation"}' -o out.xlsx
   ```
4. 验收脚本（`scripts/acceptance/*.py`）就是一份可执行的接口用例集，
   想快速确认某个模块是否正常，直接跑对应脚本即可。
