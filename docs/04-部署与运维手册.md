# 04 · 部署与运维手册

> 项目：**lab_reserve · 实验室预约管理系统**

## 1. 环境要求

| 项 | 版本 / 说明 |
|---|---|
| 操作系统 | macOS / Linux（Windows 建议 WSL2） |
| JDK | **17+**（`JAVA_HOME` 必须指向它，`dev.sh` 直接依赖） |
| Maven | 仓库自带 `./mvnw`（3.9.9），无需本机安装 |
| Node.js | 18+（前端 Vite 6） |
| Docker | 24+ 与 Docker Compose v2（跑 MySQL / Redis / Qdrant） |
| 端口 | 8080（后端）、**6173**（前端 dev）、3306、6379、6333/6334（Qdrant）、1025（可选，本地调试 SMTP） |

## 2. 配置凭据（`.env`）

根目录 `.env`（**不进 Git**，`.env.example` 是模板）：

```bash
cp .env.example .env
```

必填 / 常改项：

| 变量 | 说明 |
|---|---|
| `MYSQL_ROOT_PASSWORD` / `MYSQL_PASSWORD` | 数据库密码（compose 与服务共用） |
| `REDIS_PASSWORD` | Redis 密码 |
| `JWT_SECRET` | JWT 密钥，长度 ≥ 32（启动时会校验） |
| `MAIL_HOST` / `MAIL_PORT` / `MAIL_USERNAME` / `MAIL_PASSWORD` | SMTP；**QQ 邮箱用授权码**，不是登录密码 |
| `MAIL_SMTP_AUTH` / `MAIL_SMTP_SSL` | QQ 邮箱 `true/true`；本地调试 SMTP 用 `false/false` |
| `OSS_ENDPOINT` / `OSS_BUCKET` / `OSS_ACCESS_KEY_ID` / `OSS_ACCESS_KEY_SECRET` | 阿里云 OSS（故障图片）；bucket 需**公共读** |
| `OSS_DIR_PREFIX` | OSS 目录前缀（默认 `lab-reserve`） |
| `QUEUE_CANDIDATE_TIMEOUT_MINUTES` / `QUEUE_BAN_DAYS` | 候补确认时限（默认 30 分钟）/ 禁入天数（默认 7） |
| `RAG_ENABLED` | RAG 模块开关（默认 `false`；开启需 DashScope 与 Qdrant） |

> ⚠️ 任何凭据**只允许出现在 `.env`**，不得写进 `.md` / `.yml` / `.java` / 提交历史。

## 3. 一键启动（本机开发，推荐）

```bash
./dev.sh start      # docker 起 mysql+redis+qdrant → 后端 mvnw spring-boot:run → 前端 npm run dev
./dev.sh status     # 三个进程/容器的状态
./dev.sh logs backend    # 跟日志（backend | frontend | db）
./dev.sh restart    # 改完配置/迁移后重启后端与前端
./dev.sh stop       # 停后端与前端（数据库容器保留）
./dev.sh down       # 连数据库容器一起停
```

访问：

| 用途 | 地址 |
|---|---|
| 前端（dev） | http://localhost:6173 |
| 后端 | http://localhost:8080 |
| 接口文档 | http://localhost:8080/doc.html |
| 健康检查 | `POST http://localhost:8080/api/system/health` |

首次启动会：拉镜像 → Flyway 建表（V1–V11）→ `DataSeeder` 灌演示数据（用户/资源/预约/消息）。

## 4. Docker 全量部署（验收/演示机）

```bash
docker compose up -d --build     # db + redis + qdrant + backend + frontend(nginx:80)
docker compose ps
docker compose logs -f backend
```

- 前端由 nginx 托管静态资源并把 `/api` 反代到后端容器；
- `FRONTEND_PORT`（默认 80）控制前端容器对外端口；
- 数据库数据在 named volume，`docker compose down` 不会丢，`down -v` 会清空。

## 5. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 启动报 `Access denied for user ...` | `.env` 未加载或密码不匹配；`./dev.sh` 会自动 `source .env`，手工启动需自行 export |
| 启动报 `Found more than one migration with version X` | `backend/target/classes/db/migration` 有旧编译产物；`cd backend && ./mvnw clean` 后重启 |
| 启动报 `RAG_ENABLED=false` 时缺 `ChatClient` / `QdrantClient` | RAG 模块的部分组件无条件依赖这些 Bean；本机先设 `RAG_ENABLED=true`（或由 RAG 负责人补 `@ConditionalOnProperty`） |
| 前端 6173 打不开 | `./dev.sh status` 看前端是否运行；端口占用时 `./dev.sh logs frontend` |
| 侧边栏只有首页 | 登录后未拉取菜单；已修复（登录自动 `get_info`），若仍异常清 localStorage 重登 |
| 邮件一直"投递中" | SMTP 未配置（`MAIL_USERNAME` 为空或仍是 `change-me@`）消费者会暂停；配好后消息会继续投递。当前开发机已配置真实 QQ 邮箱 |
| 邮件进"死信" | `MAIL_PASSWORD` 是登录密码而非授权码，或端口/SSL 不匹配；投递记录页能看到失败原因 |
| 图片上传报"文件内容非法" | 服务端校验文件头魔数，改了后缀的文本会被拒；请上传真实 jpg/png/webp |
| 图片上传成功但页面 403 | OSS bucket 不是公共读；改为公共读或配置 `OSS_CUSTOM_DOMAIN` |
| 预约提交报"系统繁忙" | 并发抢同一时段，拿锁超时；刷新后重试（并发验收要求"恰好 1 条成功"） |
| 候补通知没收到 | 看排队状态是否 `NOTIFIED`；SMTP 未配置时只有站内信 |

## 6. 数据备份与恢复

```bash
# 备份
docker exec lab-reserve-mysql sh -c 'exec mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" lab_reserve' > backup_$(date +%F).sql

# 恢复（先停后端，避免写入）
./dev.sh stop
docker exec -i lab-reserve-mysql sh -c 'exec mysql -uroot -p"$MYSQL_ROOT_PASSWORD" lab_reserve' < backup_2026-10-24.sql
./dev.sh start
```

**全新重建**（会清空数据并重新灌种子）：

```bash
docker compose down -v && ./dev.sh start
```

Redis 里是业务数据（排队队列 / 收件箱 / 未读数），**不建议**随意 `FLUSHALL`；
真的清了也没关系：未读数按库重建，队列由每天的 `QueueReconcileJob` 与 DB 对账补回。

## 8. 定时任务一览

| 任务 | 频率 | 作用 |
|---|---|---|
| 邮件消费 | 2s | Redis Stream 投递邮件，失败留 PEL |
| 邮件重投/死信 | 30s | `XAUTOCLAIM` 重投；达上限进死信并回写 `DEAD` |
| 候补超时扫描 | 30s（可配） | 超时 → 7 天禁入 → 顺延下一位 |
| 预约过期扫描 | 1h（可配 `RESERVATION_EXPIRE_INTERVAL_MS`） | `APPROVED` 且结束时刻已过的预约 → `EXPIRED` |
| 未读数校正 | 每小时 | 按库重算未读数写回 Redis |
| 已删消息清理 | 每天 03:30 | 物理删除 30 天前 `is_deleted=1` 的消息 |
| 排队对账 | 每天 04:20 | Redis 队列与 DB 活动记录对齐 |

## 9. 安全与运维底线

- 凭据只在 `.env`；线上必须更换 `JWT_SECRET` 与数据库密码；
- 生产环境删除演示数据脚本或改掉全部演示密码（默认 `123456`）；
- 任何表、日志、导入文件都不允许出现身份证号；
- 手机号默认脱敏，查看完整手机号必须留 `QUERY_PHONE` 日志；
- Redis 使用 `maxmemory-policy noeviction`（队列/收件箱是业务数据，不能被淘汰）；
- 备份策略：每日 `mysqldump`；OSS 建议配置生命周期规则清理测试图片。
